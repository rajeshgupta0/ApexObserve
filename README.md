## 🔭 Overview

**ApexObserve** is an advanced, distributed observability and monitoring platform designed for complex microservices architectures. By combining robust telemetry ingestion (OpenTelemetry) with real-time dependency mapping and AI-driven predictive insights, ApexObserve transforms raw infrastructure data into actionable intelligence.

### The Problem It Solves
In modern, distributed architectures, diagnosing failures is like finding a needle in a haystack. When a single service degrades, it creates a cascading ripple effect across dozens of upstream dependencies. ApexObserve solves this by mapping the entire service topology in real-time, instantly correlating metrics and traces, and utilizing Machine Learning to proactively detect anomalies, identify the true root cause, and calculate the downstream blast radius.

## ✨ Key Capabilities

- **Intelligent Root Cause Analysis (RCA) & Evidence:** Automatically correlates distributed traces and logs to isolate the exact microservice and endpoint causing an incident, providing concrete evidence for rapid resolution.
- **Blast Radius Prediction:** Maps the downstream impact of a degraded service across the entire dependency graph, allowing teams to prioritize triage based on user impact.
- **Real-Time Alerts & Incident Lifecycle:** Evaluates health metrics against dynamic thresholds to trigger alerts and automate incident creation.
- **Health & Metrics Dashboard:** Offers a comprehensive, unified view of system health, error rates, latencies, and OpenTelemetry metrics.
- **Failure-Injection Demo Environment:** Ships with a complete suite of synthetic microservices and a traffic generator that injects real, observable failures (e.g., simulated inventory database drops) to demonstrate the platform's capabilities instantly.

## 🏗 Architecture

ApexObserve leverages a highly scalable, polyglot technology stack:

### Telemetry Pipeline
1. **OpenTelemetry Collector:** Acts as the centralized receiver for all distributed traces and metrics generated by the microservices.
2. **Apache Kafka (KRaft):** Provides a high-throughput, fault-tolerant event streaming backbone to buffer and distribute telemetry data asynchronously.
3. **PostgreSQL + TimescaleDB:** Serves as the primary time-series data store, optimized for high-ingest rates and complex analytical queries.
4. **Redis:** utilized for rapid caching and intelligent rate limiting.

### Core Services
- **Frontend (Next.js/React):** A responsive, modern dashboard tailored for SREs and DevOps engineers.
- **Backend Microservices (Java 21 / Spring Boot):**
  - `api-gateway`: Unified entrypoint for management, routing, and querying.
  - `ingestion-service`: Consumes telemetry from Kafka and writes optimized batches to TimescaleDB.
  - `processing-service`: Correlates metrics, detects statistical anomalies, and normalizes telemetry.
  - `query-service`: Powers complex GraphQL-style queries, dependency graphs, and health scores.
  - `alerting-service`: Evaluates alerting rules and manages the incident lifecycle.
- **AI Service (Python 3.10 / FastAPI):** Provides advanced telemetry intelligence. Utilizes **Isolation Forests** for anomaly detection and **Linear Regression** for predictive capacity planning and latency forecasting.

## 🚀 Getting Started

### Prerequisites
- **Java 21**
- **Node.js** (v20+ recommended)
- **Python 3.10+**
- **Docker Desktop**

### 1. Environment Setup
Clone the repository and configure your local environment variables:
```bash
git clone https://github.com/rajeshgupta0/ApexObserve.git
cd ApexObserve
cp .env.example .env
```
*(Ensure you configure the `POSTGRES_PASSWORD` and base URLs in the `.env` file if not using defaults).* 

### 2. Launch Infrastructure
Start the Kafka, Redis, PostgreSQL, and OpenTelemetry infrastructure:
```bash
docker-compose up -d
```

### 3. Start Backend & Demo Services
Use the provided PowerShell script (Windows) to compile and launch the Java microservices:
```powershell
.\start-all.ps1
```

### 4. Start AI Intelligence Service
```bash
cd ai-service
python -m venv venv
# Activate venv: .\venv\Scripts\activate (Windows) or source venv/bin/activate (Unix)
pip install -r requirements.txt
uvicorn main:app --port 8005
```

### 5. Start the Frontend Dashboard
```bash
cd frontend
npm install
npm run dev
```
The dashboard will be available at `http://localhost:3000`.

### 6. Run the Failure-Injection Demo
ApexObserve includes a built-in traffic generator that simulates real-world user activity across the demo microservices (`api-gateway-demo`, `user`, `order`, `payment`, `inventory`, `notification`). 

Run the generator to populate the dashboard with live telemetry:
```powershell
.\generate-traffic.ps1
```
Watch the dashboard as the system artificially injects latencies and errors, triggering the AI Service to automatically perform Root Cause Analysis and isolate the failing component!

## ⚠️ Limitations & Known Issues
- **Local Development Focus:** The current configuration is optimized for local demonstration and development. Production deployment requires externalizing secrets to a vault, configuring TLS, and deploying via Kubernetes/Helm.
- **Data Retention:** TimescaleDB data retention policies are currently not configured by default; long-running instances may require manual data pruning.
